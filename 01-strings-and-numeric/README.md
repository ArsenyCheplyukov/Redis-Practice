# 01 — Strings & Numeric

Базовые команды над string-ключами, числовые операции, TTL inline,
условные флаги, batch-операции.

## Команды

### Чтение / запись

- `SET key value` — записать, перезаписать если есть
- `GET key` — прочитать (`(nil)` если нет)
- `MSET k1 v1 k2 v2 ...` — атомарно записать несколько
- `MGET k1 k2 ...` — прочитать несколько за один round-trip
- `MSETNX k1 v1 k2 v2 ...` — атомарно записать все только если **все** не существуют
- `APPEND key value` — дописать к существующей строке (создаст если нет)
- `STRLEN key` — длина значения

### Числовые (работают над string, парсятся как int64)

- `INCR key` — +1, создаст ключ со значением 0 если нет
- `INCRBY key N`
- `DECR key`, `DECRBY key N`
- `INCRBYFLOAT key N` — для float

### Условные флаги у `SET`

- `NX` — записать только если ключа НЕТ → `(nil)` если есть
- `XX` — записать только если ключ ЕСТЬ → `(nil)` если нет
- `GET` — вернуть **старое** значение в ответе (атомарный swap, заменяет deprecated `GETSET`)
- `EX seconds` — TTL в секундах
- `PX milliseconds` — TTL в миллисекундах
- `KEEPTTL` — сохранить старый TTL при перезаписи (по умолчанию TTL сбрасывается)
- Флаги комбинируются: `SET key val NX EX 60`

### Служебное

- `DEL key [key ...]` — удалить
- `EXISTS key [key ...]` — сколько из перечисленных существует
- `TYPE key` — тип данных (`string` / `list` / `hash` / `set` / `zset` / `none`)
- `TTL key` / `PTTL key` — секунды / миллисекунды до истечения
- `EXPIRE key seconds` — поставить TTL на существующий ключ (вернёт 0 если ключа нет)
- `PERSIST key` — снять TTL (ключ становится вечным)
- `EXPIREAT key unix-ts` — TTL по абсолютному timestamp
- `DBSIZE` — сколько ключей в текущей БД
- `OBJECT ENCODING key` — внутренний encoding (debug-команда)

## Ключевые концепты

### TYPE vs OBJECT ENCODING

Два **независимых** слоя:

| Уровень      | Что описывает                                                               | Влияет на API                     |
| ------------ | --------------------------------------------------------------------------- | --------------------------------- |
| **TYPE**     | Структура данных (5 базовых: string, list, hash, set, zset)                 | Да, определяет применимые команды |
| **ENCODING** | Внутреннее представление в памяти (`int`, `embstr`, `raw`, `listpack`, ...) | Нет, чисто оптимизация            |

Encoding может скакать (`int` → `embstr` после APPEND) — TYPE при этом не меняется. Encoding нужен только при дебаге памяти/оптимизации. В обычном коде используй только `TYPE`.

### Числа в Redis

Отдельного типа `integer` нет. Числа — это string, которая **парсится как int64 в момент INCR**. Если значение не парсится — `(error) ERR value is not an integer or out of range`. Никакой type coercion при `SET` нет, проверка происходит ТОЛЬКО в момент числовой операции.

### TTL коды

| Возврат `TTL` | Значит                                          |
| ------------- | ----------------------------------------------- |
| `≥ 0`         | секунд до истечения                             |
| `-1`          | ключ существует, **TTL не установлен** (вечный) |
| `-2`          | ключ **не существует**                          |

Критично различать `-1` и `-2`: первое — отсутствие TTL, второе — отсутствие ключа. В проде на этом строят разные branches логики.

### TTL сбрасывается на write по умолчанию
SET temp v1 EX 100
TTL temp                  → 100
SET temp v2               → TTL сброшен в -1 (вечный!)
SET temp v3 EX 100
SET temp v4 KEEPTTL       → TTL сохранён

Это типичная причина "кэш почему-то перестал инвалидироваться". `SET` без `KEEPTTL` стирает TTL. Команды модификации (`APPEND`, `INCR`, `GETSET` и т.д.) — **TTL НЕ сбрасывают**. Только полный `SET`.

### Идемпотентность через NX

```
SET user:email:alice@example.com 42 NX  # OK
SET user:email:alice@example.com 99 NX  # (nil) — состояние не меняется
SET user:email:alice@example.com 99 NX  # (nil) — снова не меняется
```

Повторный вызов с тем же эффектом = идемпотентная операция. Безопасна для ретраев на сетевых ошибках. `SET` без флагов — НЕ идемпотентен (каждый вызов перезаписывает).

### Атомарность vs SQL-транзакция

`MSET` атомарен на уровне Redis (другие клиенты не увидят промежуточное состояние) — но это **не транзакция в SQL-смысле**, нет rollback. Все ключи запишутся, либо все не запишутся (если синтаксическая ошибка). Для "записать N ключей только если все не существуют" — `MSETNX`. Для смешанной логики (часть с условием, часть без) — `MULTI/EXEC` (изучается отдельно).

## Конвенции

### Разделитель в ключах — двоеточие, не точка

Redis принимает любые байты в ключе, но **стандарт экосистемы — `:`**:

- `user:42:profile`
- `cache:order:1001:items`
- `session:tok_xyz`

Причины:

- все доки, туториалы, чужой код используют `:`
- инструменты типа RedisInsight группируют по `:` в дерево автоматически
- `SCAN MATCH "user:*"` — стандартный паттерн namespacing

## Типичные ошибки этой сессии

- **Точка вместо двоеточия в ключе** (`views.home` → правильно `views:home`)
- **Путаница TYPE и ENCODING:** считать что `OBJECT ENCODING` возвращает "тип". Возвращает encoding (внутреннее представление); `TYPE` возвращает структуру данных. Словари двух команд не пересекаются.
- **Несуществующие команды:**
  - `MSETXX` — нет такой команды, только `MSETNX`
  - `nano` как тип — нет, есть `none` (TYPE для несуществующего ключа)
- **Синтаксис `SET` с TTL:** TTL передаётся **флагом** (`SET key val EX 30`), не позиционным аргументом

## Distributed lock — фундамент заложен

Финальная задача блока (`SET session:tok_xyz user:42 NX EX 60`) — это упрощённая версия distributed lock: атомарное "создать только если нет + автоистечение". Полная реализация с уникальным значением и безопасным релизом (через Lua script) — в `99-recipes/` позже.

## Источники справки внутри Redis

- `HELP` — общая справка
- `HELP @string` / `@hash` / `@list` / `@set` / `@sorted_set` / `@generic` / `@server` — по группам
- `HELP SET` — справка по конкретной команде
- `COMMAND COUNT` — сколько всего команд (Redis 8: 416)
- `COMMAND INFO SET` — программный реестр

Для complexity и edge cases — `https://redis.io/commands/<name>`.
