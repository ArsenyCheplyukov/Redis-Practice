# 03 — Lists

Двусторонняя очередь (deque). Не массив. Внутри — `listpack` для малых,
`quicklist` (linked list из listpack-узлов) для больших.

## Ключевая характеристика

- Push / pop на ОБОИХ концах — **O(1)**
- Доступ к середине (`LINDEX`, `LSET` с большим индексом) — **O(N)**

→ Использовать как **очередь, стек, recent-N список**.
→ **НЕ использовать** как array с random access по индексу.

## Команды

### Вставка

- `LPUSH key v1 v2 ...` — слева. **Порядок аргументов инвертируется в списке** (каждый идёт слева от предыдущего).
- `RPUSH key v1 v2 ...` — справа. Порядок аргументов сохраняется.
- `LPUSHX` / `RPUSHX` — только если ключ существует.

### Извлечение

- `LPOP key [count]` — удалить и вернуть слева (с count — несколько)
- `RPOP key [count]` — справа
- `BLPOP` / `BRPOP key timeout` — **блокирующий** pop, ждёт элемент до N секунд. Основа queue workers.

### Чтение

- `LRANGE key start stop` — срез, **включительные** границы с обеих сторон, `-1` = с конца
- `LINDEX key i` — значение по индексу, **O(N) для середины**
- `LLEN key` — длина

### Модификация

- `LSET key i value` — заменить, O(N) для середины
- `LREM key count value` — удалить N экземпляров. `count > 0` от начала, `< 0` от конца, `0` — все.
- `LTRIM key start stop` — оставить только указанный диапазон, **включительные** границы
- `LMOVE src dst LEFT|RIGHT LEFT|RIGHT` — атомарно переместить элемент из одного списка в другой (для reliable queue паттерна)

## Slicing model — отличается от Python

|                            | Python                  | Redis                       |
| -------------------------- | ----------------------- | --------------------------- |
| `list[0:5]` / `LRANGE 0 5` | 5 элементов (exclusive) | **6 элементов** (inclusive) |
| Все элементы               | `list[:]`               | `LRANGE 0 -1`               |

Оставить первые N (новейших после LPUSH): `LTRIM key 0 N-1`.

## Use cases

| Паттерн                            | Команды                                                             |
| ---------------------------------- | ------------------------------------------------------------------- |
| **Recent-N (история, активность)** | `LPUSH` + `LTRIM 0 N-1`                                             |
| **Queue (producer-consumer)**      | producer: `LPUSH`, consumer: `BRPOP` (FIFO)                         |
| **Reliable queue (без потерь)**    | `LMOVE pending working LEFT RIGHT` — атомарно перевести в обработку |
| **Stack (LIFO)**                   | `LPUSH` + `LPOP` (или RPUSH + RPOP)                                 |
| **Capped log**                     | `LPUSH` + `LTRIM`, читать через `LRANGE`                            |

## Типичные ошибки

- **`LTRIM 0 5` чтобы оставить 5 элементов** — неверно. Оставит 6 (включительные границы). Правильно: `LTRIM 0 4`.
- **`LPUSH key a b c` ожидая порядок `a b c` в списке** — неверно. Получишь `c b a` (каждый аргумент идёт слева).
- **`LINDEX` для random access** — работает, но O(N). Если нужен random access по числовому индексу — это сигнал что нужен другой тип данных (sorted set по score, или просто хранить в hash).
- **LPUSH + LTRIM в две команды без атомарности** — между ними другой клиент может вставить. В проде — `MULTI/EXEC` или pipeline.

## Encoding

- `listpack` — компактное представление до 128 элементов (по умолчанию), элементы ≤ 64 байт
- `quicklist` — linked list из listpack-узлов, для больших списков

Лимиты в `redis.conf`:

- `list-max-listpack-size -2` (размер каждого узла quicklist, отрицательные значения = в KB)
- `list-compress-depth 0` (LZF-сжатие узлов глубже N от концов; 0 = без сжатия)

## Не покрыто в этой сессии

- `BLPOP` / `BRPOP` практически — нужно два клиента одновременно
- `LMOVE` / `BLMOVE` — reliable queue паттерн
- Pipeline / MULTI для атомарности LPUSH+LTRIM
- Stream (`XADD` и т.д.) — отдельный тип для append-only логов, не list
